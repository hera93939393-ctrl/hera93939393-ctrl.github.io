<p class="lead">숫자 판정을 넓히는 아이디어 세 가지를 만들었다. 셋 다 일부러 깨 보는 시험(공격 워크플로)에서 새 구멍이 나왔다. 그래서 둘은 기본으로 꺼 두고, 하나는 넣지 않았다. 대신 "파랑을 얼마나 믿을 수 있나"를 색으로 보여 주는 쪽으로 방향을 바꿨다.</p>

## 오늘 한 일
- **잠정치 해 표시 칠하기** → 보고서의 `(’26p)` 같은 잠정치 표시는 맞든 틀리든 아예 안 칠해지고 있었다 → 이제 p까지 원본과 견준다. 원본은 잠정치인데 보고서가 p를 빼면 해 표시를 빨강으로 칠한다. 확인용 시험의 알아봄이 0.545에서 0.636으로 올랐다.
- **옛 시험 예시의 이름 바꾸기** → 예전 시험 예시와 설명글에 실문서에서 온 기관 이름이 남아 있었다 → 파일 7개 21줄을 지어낸 이름으로 바꿨다. 한글 낱말을 가리고 고치기 전·후 줄을 맞대 보니 21쌍 모두 꼴이 같았다. 이름만 바뀌었다는 뜻이다.
- **이웃 투표**(같은 줄의 파랑 이웃을 근거로 회색 값을 파랑으로 올리는 방법) → 사용자가 낸 "어텐션처럼 서로 견주기" 아이디어에서 나왔다 → 감독 세션이 놓침 다섯 꼴을 막아 줬지만 공격 워크플로에서 새 놓침 44개가 나왔다. 만들어 두되 기본으로는 꺼 둔다.
- **기간 거름** → 보고서가 원본 목록 줄의 '1분기·2분기' 값을 맞바꿔 써도 파랑이 되던 원래 놓침을 막으려고 넣었다 → 기간이 어긋나면 파랑을 회색으로 내린다. 맞는 값을 잃는 일이 57개에서 0개로 줄어서 넣었다.
- **'두 배·절반' 말 검산** → "지난해의 두 배로 늘었다" 같은 문장을 원본 두 해 값으로 검산하려 했다 → 공격 세 차례에서 구멍이 59·67·38개 나왔다. 기본 꺼짐으로 커밋했다.
- **사실 카드 약점 셋 고치기 시도** → 원본 줄 이름 번짐·비교 기준 해·음수 부호를 고치려 했다 → 이름 번짐과 비교 기준 해는 고칠 때마다 맞는 값을 20~28개씩 잃어서 넣지 않았다. 음수 부호는 다른 작업창이 새 파일로 맡았다.
- **파랑 근거 등급 설계** → 약한 파랑(이름이 안 겹치거나 해가 다른 파랑)을 진한 보라로 보여 주고, 약한 파랑만 모델로 다시 읽게 하는 설계를 썼다. 코드는 아직 안 고쳤다.
- **학습기록에 회색 까닭 남기기** → 실사용에서 회색이 왜 생기는지 모으려고 → 까닭별 건수(정수만, 글 조각 없음)와 채팅 "시간 15/6" 한 줄을 기록하게 했다.
- **오래된 작업 폴더 정리** → 11-09부터 남아 있던 따로 작업 폴더(worktree, 한 저장소를 여러 폴더에서 나눠 쓰는 기능)를 치웠다 → 커밋 안 한 39줄을 브랜치에 먼저 보존하고 폴더만 지웠다.
- **남이 만든 한글 읽기 스킬과 견주기** → 같은 공개 표본 18개와 같은 정답으로 쟀다 → 본문 같은줄비율은 0.786 대 0.976, 표 칸맞춤은 0.146 대 1.000으로 우리 읽기가 앞섰다.
- **확인용 원본 24개 심기 준비** → 사용자가 새로 넣은 원본을 건수만 셌다 → 바로 심을 수 있는 것은 16개다. 정답 파일을 '*정답*.hwp'로만 찾아서 8개가 막혀 있다.

## 막혔던 것과 푼 방법

**① "놓침 0"은 내가 지은 문제에서만 0이었다.**
이웃 투표를 처음 만들었을 때 우리가 손으로 지은 문항에선 틀린 값이 파랑이 되는 일이 없었다. 그런데 감독 세션이 이름과 수를 새로 지어 넣자 바로 구멍이 났다. '1분기·2분기' 두 값을 맞바꾼 글이 둘 다 파랑이 됐다. 처음엔 "원래 코드에도 있던 놓침"이라고 봤다. 감독이 이웃 층을 켠 판과 끈 판을 같이 돌려 보니, 끈 판에선 회색이었다. 이웃 층이 만든 놓침이었던 거다.

고칠 때마다 감독은 새 꼴을 지어 왔다. 달 꼴('3월·4월'), 한 칸 밀림, 한 줄에 대상이 둘인 꼴이 그렇게 하나씩 막혔다. 그래도 불안해서 사용자가 "혼자 말고 오케스트레이션으로" 하자고 했다. 탐색 다섯 갈래와 검증으로 짠 공격 워크플로(여러 AI가 일부러 틀린 문항을 지어 깨 보는 자동 작업)를 돌리자 새 놓침이 44개 나왔다. 손으로는 끝까지 못 찾았을 숫자다. :)

**② 빈 폴더인 줄 알았는데 진짜 폴더로 가는 통로였다.**
작업 폴더를 지운 뒤 껍데기가 남았다. 감독 세션이 "파일 0, 빈 폴더"라고 알렸다. 그런데 그 안의 `node_modules`는 진짜 `node_modules`를 가리키는 정션(Windows의 폴더 연결)이었다. 파일을 세는 명령이 연결을 따라가지 않아서 비어 보였을 뿐이다. 그대로 `rm -rf`를 했으면 진짜 폴더를 지울 뻔했다. 연결만 먼저 떼고 지웠고, 진짜 쪽 항목 149개가 그대로인 것도 확인했다.

## 오늘 정한 것과 그 이유
- **잠정치를 p 없이 쓰면 해 빨강** → 잠정치와 확정치를 섞지 않는다는 앞선 규칙을 따랐다. 숫자는 맞으면 파랑이라, 사람은 p만 붙이면 된다.
- **해가 틀린 줄의 숫자는 회색 그대로** → 해가 틀렸는지 숫자가 틀렸는지 가를 수 없다. 빨강의 정확도를 지키는 쪽을 골랐다.
- **옛 예시 이름도 모두 지어낸 이름으로(1안)** → 실문서 글은 코드에 넣지 않는다는 원칙 때문이다. 이미 올린 옛 기록은 그대로 뒀다.
- **이웃 투표는 기본 꺼짐(결정 2 ①), 기간 거름만 넣음(1안)** → 이웃 투표는 공격에서 새 놓침이 44개 나왔다. 기간 거름은 파랑을 회색으로 내리기만 하고 빨강은 안 만든다. 잃을 게 적은 쪽이라 넣었다.
- **두 배·절반 검산도 기본 꺼짐(1안)** → 공격할 때마다 새 구멍이 나왔다. 규칙만으로는 끝이 안 보였다. 공격 문항 약 400개는 다음 단계(모델이 식을 세우고 코드가 검산)의 잣대로 저장소 밖에 남겼다.
- **사실 카드 약점 둘은 넣지 않음(결정 2 1안)** → 수상한 꼴을 찾아 회색으로 내리는 사후 거름은 늘 맞는 값을 잃었다. 그래서 '파랑 근거 등급 + 모델 읽기'로 방향을 바꿨다.
- **약한 파랑은 색으로(진한 보라), 색은 모두 6가지** → 사용자 원칙 "파랑 아닌 색은 다 보고, 파랑은 다시 안 본다"를 따랐다. 파랑에 메모만 달면 아무도 안 본다. 모델이 다시 읽는 줄은 10줄까지로 정했다.
- **빠른 평가 기준선을 새 실행으로 바꿈(결정 2 ①)** → 문항이 51개 값에서 85개 값으로 늘자 합계 비율이 내려가 늘 '나빠짐'이 떴다. 같은 문항끼리 견주면 나빠진 게 없었다.
- **오래된 작업 폴더는 보존 커밋 뒤 정리(1안)** → 기능별로 골라 가져오는 일은 나중에 따로 한다.
- **이웃 투표 2차는 실사용 회색 까닭 건수가 쌓인 뒤** → 실제로 어디서 회색이 나는지부터 본다.

## 공부하며 헷갈렸던 것·물어본 것
- **문서당 걸린 초가 늘 '나빠짐'으로 뜬다** → 그날 PC 탓인지 코드 탓인지는 따로 재야 안다. 직전 실행과 문항별 비율로 견줬다(중앙 1.02). 순수 길도 고치기 전·후를 번갈아 쟀다. 오늘 커밋 탓이 아니었다.
- **문항이 늘면 합계 비율이 내려간다** → 그게 곧 나빠졌다는 뜻은 아니다. 같은 문항끼리 따로 맞대 봐야 안다.
- **부정문은 '지 않'만이 아니다** → 조사가 끼거나("늘지는 않았다") 문장 끝에서 유보하는("늘었다고 보기 어렵다") 꼴도 있다.
- **"같은 읽기 도구를 쓴다"던 외부 스킬** → 알고 보니 읽기는 자체 파서였다. 표에서 병합 칸을 안 채우고, 칸 안 줄바꿈을 칸 둘로 쪼개서 표 점수가 낮았다.
- **'이름만 바뀌었나' 세는 법** → 한글 낱말을 가리고 전·후 줄 꼴을 맞대면 한 번에 셀 수 있다.
- **블로그 게시 명령이 자동 승인 검사에 막혔다** → 사용자가 `!`로 직접 실행했다. `!`는 Git Bash라 역슬래시 경로가 지워진다. 경로는 슬래시로 쓴다.

## AI가 한 것을 고친 것과 그 이유
- **"분기 맞바꿈 놓침은 이웃 층과 무관"이라는 보고** → 목록 꼴만 보고 단정했다. 감독이 켬·끔을 둘 다 재현해서 이웃 층 탓임을 밝혔다. 앞으로 켬·끔 둘 다 돌려 보고 말한다.
- **손으로 지은 문항으로만 "놓침 0"이라 봄** → 공격에서 44개가 나왔다. 판정을 올리는 고침은 커밋 전에 공격 워크플로를 늘 돌리기로 했다.
- **기간 거름 첫 판이 맞는 값 57개를 내림** → 기간을 글자 그대로 견준 탓이었다. '달 묶음'으로 다시 짜서 0개가 됐다.
- **빈 글이면 참이 되는 조건 `x[-1:] in "pP"`** → 감독이 짚어서 `.lower() == "p"`로 고쳤다.
- **두 배 검산 커밋 때 같은 규칙을 보는 다른 자가시험을 안 돌림** → 감독이 깨끗한 두 판을 견줘 원인 커밋을 찾았다. 한 줄로 고쳤다.
- **"빈 폴더" 보고** → 실제로는 정션이었다. 앞으로 지울 폴더는 연결인지부터 본다.
- **감독 세션이 "시작" 알림 없이 한글 모듈까지 돌림** → 전체 자가시험에 한글 모듈이 섞여 있는 줄 몰랐다. 띄운 한글이 모두 닫힌 것을 확인하고 스스로 알렸다. 앞으로 돌릴 갈래를 골라서 돌린다.
- **외부 스킬 견줌에서 표 문항이 0개** → '표본' 폴더만 공개로 걸렀기 때문이다. 일지로 검색표본도 공개 사본임을 확인하고 넣었다.
- **비율 문항 하나를 잘못 지음** → '두 배 가까이 틀림'으로 만든 문항이 실제로는 1.9배라 거의 두 배였다. 다시 지었다. 보고서 쪽만 좁히면 된다는 짐작도 틀렸다. 3차 공격은 원본 읽기 쪽 약점을 찾아냈다.
- **사용자의 "보라색?"을 빈 자리 재사용으로만 읽음** → '색 5가지' 결정과 부딪힌다는 걸 먼저 짚지 못했다. 사용자가 짚어 줬다.

## 배운 것
> 판정을 넓히는 고침은 내가 지은 시험이 아니라, 깨려고 덤비는 시험을 통과해야 들어간다. 못 통과하면 꺼 둔다. 안전한 회색이 위험한 파랑보다 낫다.
