<p class="lead"> 오늘은 집사 모델을 내 문서 꼴에 맞게 따로 가르칠 준비를 마치고, 결재 전에 숫자가 서로 맞는지 보는 기능을 손봤다. 가장 크게 배운 건 시험을 통과한 고침도 실제 한글 문서 앞에서는 무너질 수 있다는 점이었다. </p>

## 오늘 한 일
- **LoRA 준비 스크립트 넷(LoRA: 큰 모델을 통째로 다시 가르치지 않고 작은 덧판만 붙여 버릇을 바꾸는 방법)** → 집사가 쓴 글을 내가 매번 고치는 수고를 줄이려고 → 학습 자료 만들기, 훈련, 올라마(내 PC에서 모델을 돌리는 프로그램)에 올리기, 새 모델과 원래 모델 비교까지 한 줄로 이었다. 가짜 자료 자가시험을 다 통과했고, 일부러 심은 버그 9가지도 다 잡아냈다.
- **비교 규칙 다시 세우기** → 같은 모델을 두 번 돌렸는데 '지어낸 숫자' 합이 14 대 5로 흔들렸다. 이대로면 운에 따라 판정이 바뀐다 → 짝끼리 견주는 부호 검정(둘 중 어느 쪽이 나빠졌는지만 세어 우연인지 가리는 통계 방법)으로 바꿨다. 사람이 A/B를 모르고 고르는 블라인드 판정도 '채택 문'으로 더했다.
- **결재 전 점검 보강** → 같은 수치가 여러 곳에서 맞는지, 표 안 합계, 글 속 비율, 날짜·요일을 볼 때 놓치는 게 많았다 → 가짜 시험지 26문제를 만들어 재 보고 하나씩 메웠다.
- **색인 검색 속도** → 질문 하나에 28초씩 걸려 쓰기 답답했다 → SQLite FTS5(데이터베이스에 붙는 전문 검색 색인)로 후보를 먼저 걸러냈다. 결과 순위와 점수는 예전과 똑같다.
- **AI 세션 셋이 밤사이 일을 나눠** → 내가 자는 동안 GPU 확인, 검색 속도 개선, 표 읽기 버그를 각자 맡았다. 서로 파일을 안 건드리고, 공개 저장소에는 올리지 않는다는 규칙을 먼저 정했다.

## 숫자로 본 변화

| 항목 | 전 | 후 |
|---|---|---|
| 물음 검색(실제 색인) | 28초 | 0.84~1.51초 |
| 같은 수치 확인 (가짜 시험지) | 2/5 | 2/5 (그대로) |
| 표 안 계산 | 4/7, 거짓 빨강 2 | 7/7, 거짓 빨강 0 |
| 글 속 계산 | 4/7 | 6/7 |
| 날짜·요일 | 1/7 | 6/7 |
| 전체 26문제 | 11 | 21, 거짓 빨강 0 |
| 순수 함수 시험 | 45/45 | 45/45 |

- 같은 모델을 두 번 돌렸을 때 '고칠 양' 차이는 약 1.5%였다. 채택 문턱 10%보다 훨씬 작으니 이 지표는 믿을 만하다. 지금 모델의 고칠 양은 약 0.76이고, LoRA로 이 값을 낮추는 게 목표다.

## 막혔던 것과 푼 방법

**1. 빨강으로 칠했는데 파랑 그대로였다.**
검토를 맡겼더니 "합계는 틀렸는데 왜 파랑이냐"는 피드백이 나왔다. 처음엔 칠할 자리를 잘못 찾는 줄 알았다. 그래서 찾은 자리마다 한글의 찾기 기능을 한 번 더 부르게 고쳤다. 시험은 통과했다. 그런데 실제 샘플 사본에서는 메모가 10개, 9개, 7개로 줄더니 한글이 멈춰 버렸다. 바로 되돌렸다.

샘플을 다시 재 보니 뿌리가 셋이었다.
- 글자색만 바꾸라고 해도 라이브러리가 글꼴 종류까지 같이 넣었다. 특정 글꼴을 쓴 표에서는 한글이 이 명령을 아예 거절했다. → 글자색 하나만 보내는 함수로 바꿨다.
- 메모를 달고 나면 커서가 값 앞에 선다. 그래서 다음 값을 엉뚱한 곳(소수점 뒤 숫자, 날짜 속 숫자)에서 집었다. → 뒤 값부터 메모를 달았다. 그리고 문서 처음부터 "같은 값이 몇 번 먼저 나오나"를 세어 그만큼 건너뛰었다. 한글 찾기는 더 부르지 않는다.
- 칠하기에도 같은 셈을 썼다.

결과는 메모 10/10이 칠한 자리와 같은 곳에 달렸고, 빨강 10곳이 모두 제자리였고, 멈춤도 없었다. 이 일로 규칙을 하나 정했다. **한글과 맞물리는 고침은 샘플 사본에서 확인한 뒤에만 커밋한다.**

**2. 내가 고친 것 대부분은 '꼴'이 아니라 '사실'이었다.**
LoRA 학습 자료를 만들려고 내가 고친 기록을 들여다봤다. 진짜 고침 16개 중 13개가 메모에 없던 숫자를 내가 보탠 것이었다. 모델이 이걸 배우면 숫자를 지어내는 버릇이 든다. 그래서 학습 자료에서 뺐다. 모델에게 가르칠 건 꼴이고, 사실은 사람이 넣어야 한다는 걸 데이터가 먼저 말해 줬다 :)

**3. 내 실수 하나.**
결재 전 점검이 왜 잘못 짚는지 보려고, 짚은 자리 앞뒤 글자를 숫자만 가려서 출력했다. 그런데 실제 문서의 낱말 조각 몇 개가 AI 대화로 나갔다. 다시 해 보려 하자 자동 권한 검사가 막았다. 그 뒤로는 건수와 숫자 차이만 센다. 공개 저장소에 올리기 전에도 실제 수치가 섞였는지 미리 검사했다. 걸린 커밋은 지어낸 값으로 다시 만든 다음에야 올렸다.

## 배운 것
> 시험을 통과했다는 건 시험지를 통과했다는 뜻일 뿐이다. 실물 앞에서 다시 재 보기 전까지는 고친 게 아니다.

> 같은 걸 두 번 재서 흔들리는 지표로는 아무것도 판정하지 않는다. 먼저 흔들림이 얼마나 되는지부터 잰다.
