<p class="lead"> 숫자 하나를 "값"이 아니라 "이름·세부·해·시기·단위·대상이 붙은 한 묶음"으로 읽게 바꾼 날이었다. AI 세션 여섯이 새벽부터 밤까지 설계·공격·확인·속도를 나눠 맡았고, 레드팀이 찾아낸 헛빨강(맞는 값을 틀렸다고 칠하는 것)은 저녁까지 전부 막혔다. </p>

## 오늘 한 일
- **파랑 근거 등급(새벽)** → 값만 맞고 이름·해는 확인 못 한 파랑을 보라로 따로 칠하고, "보라를 모델이 다시 읽어 파랑으로 올리기"는 두 번 공격해 보니 틀린 값까지 올려서 기본 꺼짐으로 두었다. 음수 부호 거름도 맞는 파랑을 잃어 보류.
- **아침 결정 열 가지와 push** → 새벽에 쌓인 결정을 번호로 하나씩 물어 정하고, 밤새 멈췄던 검토확인을 다시 돌려 미push 묶음을 올렸다. 숫자 검사 기준서를 저장소의 확정 문서로, 창마다 다르던 규칙서는 한 곳에서 나눠 주는 도구로 통일.
- **숫자 신원 카드(오후)** → 숫자에 이름·세부·해·시기·단위·대상 칸을 달고, 원본에 같은 신원의 숫자가 하나뿐인데 값이 다르면 빨강. 윗줄 = 아랫줄 합일 때만 카드를 잇는 '관계' 단계까지 넣었다.
- **레드팀 공격** → 신원 빨강·관계·조사 떼기·계획 숫자를 겨눈 지어낸 문항 수백 개로 열 번 넘게 공격, 찾은 헛빨강 꼴 열다섯을 팀장이 차례로 막았다.
- **감독 확인·새 실수 심기** → 확인용 원본 23개 문서에 실수 161판을 심어 '매주 넓게 보는' 평가 묶음을 만들고, 단위 바뀜·반올림 틀림·옛 판 꼴 값이라는 새 실수 종류 셋을 심는 도구와 지표를 넣었다. 커밋 묶음마다 깨끗한 판에서 자가시험·평가를 돌려 push 전에 확인.
- **과거 자료(색인 창)** → 해 다름 색을 주황으로 합치고, 작년 잠정치와 올해 확정치를 같은 해로 짝지어 주황 메모에 "고치기 전 까닭 확인" 꼬리를 붙였다. 같은 해 과거 파일이 여럿이면 이름 끝 날짜와 '최종' 개수로 고르고, 보고서끼리 엇갈리면 나란히 보여 준다.
- **속도와 읽기** → 신원 짝 찾기를 원본 카드 색인으로 바꾸고, 원본 한글 파일은 한글 프로그램을 띄우지 않는 읽기 길을 먼저 타게 했다.
- **저녁 견본 시험** → 회색(못 고름) 메모에 원본 후보를 적는 새 꼴을 사용자가 직접 보고, 메모 안 숫자 색을 본문 색과 같게 바꿨다. 어제 글도 블로그에 게시.

## 막혔던 것과 푼 방법

**"한 줄에 숫자 하나씩"이 너무 좁았다.** 어제까지 숫자 검사는 값이 원본에 있는지만 봤다. 그러니 '정기점검 90회, 수시점검 30회'처럼 한 줄에 둘이 있으면 서로 섞이고, 다른 절의 같은 이름 '상담건수'와도 짝이 됐다. 사용자와 "숫자를 어떻게 읽는가"를 하나씩 맞췄다. "상담 뒤에 붙은 수치는 상담에 붙은 수치"라는 말에서 출발해, 숫자를 (대상·이름·세부·해·시기·단위·값) 한 묶음으로 보기로 했다. 이름으로 짝을 먼저 찾고, 그 짝이 하나뿐이고 값이 다를 때만 빨강. 윗줄과 아랫줄은 "80 = 52 + 28"처럼 숫자 논리가 설 때만 잇는다. 뜻을 짐작하지 않는다는 게 핵심이었다.

**패치와 공격이 수렴하지 않을 때.** 레드팀(일부러 틀리게 만든 문항으로 공격하는 세션)이 헛빨강 꼴을 찾으면 팀장이 막고, 레드팀은 고친 규칙의 경계(다른 기호·다른 단계·비슷한 말)를 겨눈 문항을 더해 다시 공격했다. 다섯 바퀴쯤 돌자 '현원'·'재적' 같은 새 낱말이 계속 뚫렸다. 낱말 목록으로 막는 건 늘 진다는 걸 받아들이고, **묶음 규칙**으로 바꿨다. "보라(이미 사람이 볼 값)는 빨강으로 안 바꿈", "같은 수가 원본에 같은 해로 있으면 누계 짝 안 지음", "품음은 한 줄기일 때만". 그 뒤로 헛빨강이 0으로 떨어졌다 :)

**끄개가 안 꺼지고 있었다.** 관계 단계를 켰다 껐다 견줬더니 "색 바뀜 0"이 나왔다. 성공처럼 보였지만, 팀장이 준 예시 꼴이 안 잡혀 파 보니 환경변수를 모듈 불러올 때 한 번만 읽는 끄개라 같은 프로세스에선 늘 켜진 채였다. "아무것도 안 바뀜"이 나오면 끄개가 정말 듣는지부터 의심하기로 했다.

## 오늘 정한 것과 그 이유
- 보라를 모델로 파랑에 올리는 B층은 기본 꺼짐 → 틀린 값 16개가 파랑이 됐고, 파랑은 사람이 다시 안 보는 색이라 하나라도 올리면 놓침. 우선순위는 "놓치지 않기 > 거짓 경보 > 볼 곳".
- 부호 거름(①안)은 합치지 않고 재료로 남김 → 두 번 공격 모두 맞는 파랑을 잃음, 글자 꼴로 문장 뜻을 가르는 같은 한계.
- 해 다름 색은 연보라를 버리고 주황에 합침 → 새 보라가 생겨 보라 계열 둘이 헷갈려서. 구분은 메모 머리 글로.
- push 전 확인은 48문항 짧게, 넓은 161판은 매주 일요일만 → 2시간 40분짜리 확인은 메모리로 자주 끊겨 push가 막혔다.
- 기준선은 문항이 바뀌면 옮김 → 안 옮기면 매번 '나빠짐' 소음에 진짜 나빠짐이 묻힘.
- 조용한 실패(오류를 삼키고 넘어가는 자리) 6곳은 기준선에 "확인 끝" 도장, 모델 묻기 실패는 기록에 한 줄 → 확인한 자리와 새 자리를 갈라야 다음 새 자리가 보임.
- 작년과 다른 숫자는 빨강이 아니라 주황 유지 → 고칠 일이 아니라 까닭 확인할 일. 빨강에 섞으면 빨강을 덜 믿게 됨.
- '3월말' = 1~3월 누계로 → 다만 현원('3월 현재')과 갈리는 꼴은 묶음 규칙으로 막음.
- 새 실수 종류 셋은 새 씨에만, 기본 꺼짐 → 옛 판과 기준선이 흔들리지 않게.
- 과거 판 고르기에 수정 시각은 안 씀 → 옛 판을 열어 보기만 하고 저장해도 시각이 바뀜.
- 메모 안 숫자는 본문과 같은 색으로 굵게, 회색은 흰 바탕 위에 → 연두 메모 바탕에서 회색은 어떤 톤이든 묻힘(견본 11가지 비교).
- 일 나누기는 병렬 먼저 → 같은 파일은 한 쪽만, 측정은 조각으로. 다만 한글 작업과 메모리를 나눠야.
- 집사 '대화 갈래' 할 일로 등록 → 복직 뒤 코드 고침 없이 집사와 설명·설정을 풀고 싶어서.

## 공부하며 헷갈렸던 것·물어본 것
- "조용한 실패 등록이 가르자는 거지?" → 가르기는 자리마다 이미 해 뒀고, 등록은 "넘어가도 됨" 도장. 그래야 새로 생긴 자리만 실패로 뜬다.
- 심기 도구만 넓히면 평가에도 들어가나? → 평가도 정답 파일을 따로 찾는다. 양쪽 다 넓혀야 한다.
- 글자 꼴 `*.hwp`가 `.hwpx`를 찾나? → 안 찾는다. 끝까지 맞춰 본다.
- 모델 답이 맞는데 왜 버려지나? → 모델은 굽은 따옴표를 곧은 따옴표로, 괄호까지 붙여 돌려준다. 글자 그대로 견주면 안 되고 꼴을 맞춰야.
- 두 판을 견줬더니 모든 문항이 다 '다름'? → 실행 번호 칸 때문. 색 건수는 영향 없음.
- 임시 작업 폴더에서 읽기 시험이 실패 → 코드 탓이 아니라 추적 안 되는 파일이 그 폴더에 없어서. 본 트리 기록으로 가름.
- 메모 뒤 흰 바탕을 두면 느려지나? → 토막마다 한글 명령 둘 더, 후보 셋이면 0.1초 안쪽(추정).
- `startswith(("X ", "? "))` → 튜플을 주면 "이 중 하나로 시작하면".
- 시간 지표가 '나빠짐'이면? → 다른 창 일이 섞였을 수 있어 한가할 때 한 번 더 재서 가름.

## AI가 한 것을 고친 것과 그 이유
- 이름을 기존 칸에 덮어쓴 첫 신원 판 → 틀린 보라 73개가 파랑이 되는 부작용 → 새 칸에 따로 둠.
- B층 첫 판이 이름만 보고 올려 헛파랑 15 → 증감·해까지 보게 좁힘 → 그래도 16이 더 나와 기본 꺼짐.
- 보조 에이전트가 지시서에 없던 덧규칙을 더함 → 공격에서 잃음 대부분의 원인 → 뺌.
- 레드팀이 "관계 켬/끔 색 바뀜 0"이라 알림 → 끄개가 안 꺼져 켬/켬이었음 → 돌리개가 모듈 값도 바꾸게 고치고 바로잡는 글.
- 감독의 새 실수 심기가 해·달 표시('24.3)를 소수로 봐 반올림 재현율을 10/15로 잘못 잼 → 놓침 꼴을 가려 보다 찾음 → 해 따옴표 뒤 수는 빼고 다시 심어 15/15.
- 감독이 골든셋 문항 이름 꼴을 틀리게 만듦 → 넣기 직전 사본으로 되돌리고 다시.
- 공격 문항 폴더 이름과 시험 파일 이름에 날짜 네 자리를 넣어 실수치 검사에 걸림 → 네 자리 숫자 금지 규칙을 이름에서 놓침 → 사용자 허용, 앞으로 이름은 낱말로. 시험 쪽은 점 꼴로 고침.
- 팀장이 "커밋됨"이라 보고했으나 import 하나 빠져 실제론 안 됨 → 감독이 git으로 잡음 → 커밋 뒤엔 로그를 보고 말하기로.
- 팀장이 과거 자료 고침을 "주석만"이라 했으나 코드 한 곳 바뀜 → 색인 창이 짚어 커밋 메시지에 적음.
- 팀장이 표 칸 메모에 꼬리를 따로 붙이려 함 → 같은 함수를 부르므로 두 번 붙음 → 색인 창이 알려 막음.
- 감독 역할 문서 첫 판이 '한글 0·4GB'로 실제와 다름 → 감독이 다섯 곳 짚어 고침.
- 계획 숫자 첫 판이 '원본에 값 하나뿐' 지름길로 빨강이 됨 → 레드팀이 잡음 → 이름 이은 후보하고만 견줌.
- 색 못 읽으면 빨강으로 두던 메모 → 파랑·회색 값이 '틀림'처럼 보일 수 있음(감독 지적) → 굵게만.
- 집사 채팅에 적은 사용자 말이 또 문서에 들어감(두 번째 재현) → 가드를 언제 넣을지는 사용자 결정 대기.
- 색인 창이 Git Bash 안에서 파이썬으로 글자를 바꾸다 한글이 깨짐 → 규칙대로 편집 도구로.

## 배운 것
> 낱말 목록으로 막으면 늘 새 낱말에 진다. "같은 값이 다른 곳에 있으면 짝 안 지음"처럼 상황을 묶는 규칙이어야 공격이 수렴한다.

> "아무것도 안 바뀜"은 성공이 아니라 질문이다. 끄개가 정말 꺼졌는지, 답이 버려지고 있지는 않은지 먼저 본다.
