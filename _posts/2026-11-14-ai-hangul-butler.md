<p class="lead"> 한글 표를 읽을 때 칸 속에 든 표(겹표)를 따로 떼어 내자, 표 칸 위치 시험이 0.86에서 1.00이 됐다. 오후와 밤에는 기능을 더하지 않고 규칙·검사·백업 같은 안전장치를 다졌다. </p>

## 오늘 한 일
- **프로그램 분석** → 쉰 개가 넘는 모듈 속을 나도 다 모른다는 게 걸렸다 → AI 세션 하나가 코드만 읽는 분석 네 갈래를 동시에 돌려 첫 '코드 지도'를 만들었다. LLM(대형 언어 모델)을 쓰는 기능은 글쓰기 하나뿐이고 나머지 판정은 모두 코드 규칙이라는 것도 이때 확인했다.
- **표 칸 읽기 겹표 고침** → 한글이 보여 주는 표 격자와 같은 행·열에 같은 글이 오는지를 정답으로 놓고 쟀다 → 표·칸·숫자 칸 모두 1.000. 이 시험은 평가 항목 '읽기표'로 넣어 앞으로 나빠지면 바로 걸린다.
- **원본 대조 표 칸을 rhwp로** → 원본 하나 읽을 때마다 한글 프로그램을 띄우던 걸 rhwp(한글 파일을 직접 푸는 오픈소스 엔진)로 바꿨다 → 결과는 예전과 똑같고 시험 시간은 3분의 1로 줄었다.
- **글쓰기 숫자 빈틈 막기** → 분석해 보니 작성 경로 셋 가운데 '메모만으로 짧게 쓰기'에만 숫자 검사가 빠져 있었다 → 메모 밖 숫자가 나오면 바로 넣지 않고 확인 화면을 띄운다.
- **규칙·스킬·훅 정비** → 프로젝트 규칙 파일이 세션 시작 폴더에 없어서 실제로는 기억에 기대 규칙을 지켜 왔다 → 전역 규칙과 프로젝트 규칙을 나눠 새로 쓰고, 되풀이하는 절차는 스킬(정해 둔 작업 절차) 10개로, 반드시 지킬 것은 훅(명령 직전에 자동으로 도는 검사)으로 옮겼다.
- **앞문 문서 새로 쓰기** → 옛 README·기획서가 지난달 기준에 머물러 있었다 → README·PRD(제품 요구 문서)·문서 목록·코드 지도를 지금 집사에 맞게 다시 썼다. 쓰지 않는 서버 모델은 지우고 모델은 서버 9B 하나로 정했다.
- **밤 '묶음 A' 안전장치** → 로드맵에 들어가기 전에 빈틈 열 개를 짚었고, 그중 작은 것부터 했다 → 작업 기록 폴더 매일 백업, 평가 기록에 모델 판 지문 남기기, git 검사 훅 전역화, 닿는 모듈 세기 도구. 바탕화면 더블클릭 실행 파일도 만들었다.
- **자잘한 마무리** → 첨부 읽기에서 쪽 번호가 첫 쪽에 몰리던 문제와 기호 없는 굵은 소제목 찾기, 한글 XML 이름표를 인터넷 주소로 잘못 보던 망 정책 검사 오탐을 고쳤다.

## 막혔던 것과 푼 방법

**① 짝을 못 찾던 표는 거의 다 '표 속의 표'였다**
rhwp로 읽은 표 가운데 한글 격자와 짝이 안 맞는 것들의 생김새만 세어 봤다. 거의 전부가 칸 속에 표가 하나 더 든 겹표였다. 읽는 코드가 속 표를 바깥 칸 글 안에 "a | b"처럼 한 줄로 납작하게 넣고 있었다. 그러니 속 표는 따로 된 격자가 없었고, 그 표를 품은 바깥 칸의 글도 한글과 달랐다.
고친 방법은 단순했다. 속 표를 바깥 표 뒤에 따로 된 표로 꺼내고, 바깥 칸 글은 한글과 같은 차례(속 표 칸 글 → 문단 글)로 맞췄다. 그러자 표·칸·숫자 칸이 모두 1.000이 됐다. 겹표가 많은 문서에서는 숫자 칸 맞춤이 절반 남짓에서 전부로 올랐다.
남은 차이는 행·열 이름의 빈칸뿐이었다. 빈칸 여러 개, 특수 빈칸, 탭을 한글 규칙대로 다루자 그것도 사라졌다. 값과 자리는 처음부터 맞았고, 틀린 건 '빈칸을 어떻게 세느냐'였다 :)

**② 안전장치가 너무 예민하거나, 아예 안 걸렸다**
push(원격 저장소에 올리기) 직전에 실제 업무 문서의 숫자가 섞였는지 보는 '실수치 검사'를 훅으로 만들었다. 처음 돌려 보니 지난 60커밋 가운데 약 12%가 걸렸다. 열어 보니 전부 내가 시험용으로 지어낸 4자리 숫자가 실문서 숫자와 우연히 겹친 것이었다. 그래서 세 가지를 바꿨다.
- 지어낸 값은 숫자 덩어리가 없는 꼴로 쓴다.
- 기계가 쓰는 평가 표는 검사에서 정확한 경로로 뺀다.
- 오탐 허용은 사람이 직접 친 콘솔에서만 받는다. AI 창이 스스로 허용하면 거절한다.

반대로 안 걸리던 빈틈도 있었다. 훅을 모든 창에 걸리게 전역으로 옮겼는데, PowerShell에서 `Set-Location '…'; git push`처럼 쓰면 훅이 어느 저장소인지 못 알아보고 조용히 넘겼다. 이 꼴을 시험에 먼저 넣어 실패하는 걸 확인한 뒤 고쳤다. 고친 훅은 켜자마자 아직 안 올린 커밋 둘을 잡았다. 이것도 지어낸 숫자가 우연히 겹친 경우였다.

백업에서도 처음 실제로 돌릴 때 함정 둘을 만났다. 백신이 방금 복사한 파일을 붙잡아 폴더 이름 바꾸기가 거부됐고, 작업 스케줄러로 띄운 파이썬은 출력 창이 없어서 화면에 글을 쓰려다 멈췄다. 둘 다 고친 뒤 예약 실행이 깨끗이 끝났다.

## 배운 것
> 값은 처음부터 맞았다. 틀린 건 표를 '어떻게 펼쳐 놓느냐'였다. 정답과 맞대 보기 전에는 무엇이 틀렸는지도 모른다.
>
> 안전장치는 만들 때보다 처음 켤 때 더 많이 가르쳐 준다. 너무 예민하면 사람이 무시하게 되고, 조용히 건너뛰면 없는 것과 같다.
