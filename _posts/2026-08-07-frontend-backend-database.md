<p class="lead">프론트엔드-백엔드-데이터베이스 구조와 HTML·CSS·JS의 관계를 정리했다.</p>

## 한눈에 비교

| 구분 | 역할 | 사용자에게 보이는가 | 대표 기술 |
|---|---|---|---|
| 프론트엔드 (Front-end) | 사용자가 브라우저에서 직접 보고 조작하는 화면 | O (보임) | HTML, CSS, JavaScript, React, Vue |
| 백엔드 (Back-end) | 요청을 처리하는 서버 로직 (로그인 확인, 계산, 권한 체크 등) | X (안 보임) | Node.js/Express, Python/Django, Java/Spring |
| 데이터베이스 (Database) | 데이터를 실제로 저장·조회하는 저장소 | X (안 보임) | MySQL, PostgreSQL, SQLite, MongoDB |

## 프론트엔드를 이루는 3요소

| 기술 | 역할 | 비유 |
|---|---|---|
| HTML | 화면의 구조/뼈대 (제목, 버튼, 입력창의 위치) | 건물의 골조 |
| CSS | 디자인/스타일 (색깔, 크기, 배치) | 건물의 인테리어·마감 |
| JavaScript | 동작/상호작용 (클릭하면 반응, 입력값 검사) | 건물의 전기·자동문 같은 작동 장치 |

## 전체 흐름

```
사용자
  │
  ▼
[프론트엔드: HTML/CSS/JS]  ← 화면에 보이는 부분
  │  (요청 전송)
  ▼
[백엔드: 요청 처리 로직]   ← 서버에서 돌아가는 부분
  │  (저장/조회 명령)
  ▼
[데이터베이스: 데이터 저장소]
```

### 예시: 쇼핑몰 "장바구니 담기" 버튼

1. **HTML/CSS**로 만들어진 버튼을 **JavaScript**가 클릭 감지
2. JavaScript가 서버(백엔드)에 "이 상품 담아줘" 요청 전송
3. 백엔드가 요청을 받아 처리 로직 실행
4. 백엔드가 데이터베이스에 "장바구니에 저장해줘" 명령
5. 결과를 백엔드 → 프론트엔드로 돌려줘서 화면에 반영

## 정리

- HTML/CSS/JS = 프론트엔드를 **만드는 재료**
- 프론트엔드/백엔드/데이터베이스 = 웹 서비스의 **구조(계층)**

이 둘은 서로 다른 층위의 개념이라 헷갈리기 쉽지만, "프론트엔드라는 층을 HTML/CSS/JS라는 재료로 짓는다"고 생각하면 정리가 쉽다.
